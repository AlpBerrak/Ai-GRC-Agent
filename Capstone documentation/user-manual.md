## Using the GRC AI Agent
### Installation
To install and connect the GRC AI Agent, you must use n8n as the workflow engine and integrate it with a Slack workspace. At least one person in the organization must have an n8n account in order to import, configure, and activate the workflow. Once the workflow is active in n8n, it can be connected to a Slack bot so that any user in the Slack channel can access and interact with the agent without needing an n8n account themselves.

To set up the integration, first import the provided workflow JSON into n8n. After importing, configure the required credentials in n8n, including the Slack API credentials and the LLM API key (e.g., OpenAI). Next, create or configure a Slack app inside your Slack workspace and enable the necessary bot permissions (such as message reading, writing, and event subscriptions). Once the Slack bot is created, link it to the n8n workflow by copying the webhook URL from the Slack trigger node in n8n and pasting it into the Slack Event Subscriptions configuration panel.

After the Slack bot is connected, ensure it is invited to the appropriate Slack channel where users will interact with it. Finally, activate the workflow in n8n. At this point, the system is fully connected: Slack messages trigger the workflow in n8n, which then processes the request using the AI agents and returns results to Slack.

Once properly linked, any user in the Slack workspace can access the GRC AI Agent by interacting with the bot, while all execution and logic processing is handled through the n8n workflow hosted by the organization.


### Slack Process
To use the GRC AI Agent through Slack, the workflow must first be properly connected to a Slack workspace using a bot integrated with n8n. Once the setup described in the Installation section is complete, the Automated GRC Agent Bot becomes the primary interface for all user interactions. Users interact with the agent by mentioning the bot inside any authorized Slack channel. The command format is: @Automated GRC Agent Bot <message>

Any message after the bot mention will trigger the workflow. This can be a simple greeting such as “hello” or a direct request for a system assessment. Once triggered, Slack sends the event to the connected n8n workflow, where the AI agents begin processing the request.

After the bot is mentioned, the system automatically sends the user a direct message containing a structured form. This form collects the necessary inputs for the GRC analysis. The form includes questions about the organization’s system configuration, operational location, industry sector, and approximate number of users or data subjects. It also includes a self-assessment section in which users rate different components of their system's security posture on a scale of 1 to 10.

Each rating field allows the user to optionally provide justification or context. These explanations improve the quality of the analysis but are not required. If a user is unsure how to answer, they may input “I don’t know,” and the AI system will default to baseline security assumptions aligned with NIST cybersecurity standards.

Once the form is submitted, the workflow is executed in n8n. The system processes the input through multiple AI agents that analyze compliance requirements, identify security weaknesses, and map the configuration against regulatory frameworks. This process usually takes 3-7 minutes.

When analysis is complete, the Automated GRC Agent Bot sends a final direct message back to the user in Slack. All results are delivered directly in Slack, allowing users to quickly review and act on the findings without leaving the workspace.

### Executing Workflow
Once your Slack channel has the Automated GRC Bot implemented, you can execute the workflow by calling the AI Agent using the command @Automated GRC Agent Bot with any following sentence or word (e.g. “hello”) to trigger the workflow. Once the Bot has been called, you will receive a form to complete in your DMs from the Automated GRC Agent Bot. This form will walk you through a self evaluation of your organization's system configuration as well as ask you for some basic information like the location of operations for your organization, the sector your organization operates under, and the number of users your organization collects data on. Part of the self evaluation is rating, to the best of your ability, the implementation of different subsections of your organization's system configurations on a scale from 1 to 10. Additionally, you will be asked to provide an explanation for the rating you gave in order to give more context to the AI Agents for analysis. While the explanation is great for more in depth upgrade recommendations, “I don’t know” is an acceptable answer for the AI Agent. If you provide the AI Agent with “I don’t know” it will provide baseline recommendations that a system configuration should have to meet NIST standards and prevent cyber threats. After submitting the form the AI Agent will take roughly 2 - 3 minutes to execute. Once completed, the Automated GRC Agent Bot will send you another DM with the output from the AI Agents. This output will contain the regulations your organization must comply with based on the information provided via the form and possible upgrades for different subsections of the system configuration based on the ratings and information given during the self evaluation.

### Use Cases
The GRC AI Agent can be used as a tool to run risk assessments on your organization’s system configurations quickly. While this tool should not be the only way you conduct risk assessments on your system configuration, it provides a starting point in determining what aspects of a system can be upgraded to better protect an organization from cyber threats. Additionally, it can be used as an efficient way to determine what data privacy regulations apply to your organization, allowing you to stay up to date on any legislation change and avoid fines imposed on organizations that do not comply. The GRC AI Agent is an efficient way to determine if the system configurations for your organization are effective and functional, but should be used as an additional tool in a risk assessment, not the only tool in a risk assessment. 
Further Development of the GRC AI Agent
There are a few areas that the GRC AI Agent can be expanded upon to reach a wider audience and fulfill more use cases. Primarily, implementing the logic to account for different sectors, not just business and finance, would allow more users to be able to use the GRC AI Agent and get useful recommendations and feedback. In order to implement this expansion, there would need to be additional regulations added to the US Federal Data Privacy Regulations to accommodate for more sectors. The workflow’s logic would then need to be updated to account for more than one sector, as there is currently a guardrail preventing analysis from being conducted on any other sector than business and finance. New AI Agents would need to be added to the workflow that are executed depending on the sector in order to give tailored regulations and recommendations that are appropriate for the laws and standard practices in that sector. 

Additionally, added recommendations tailored to more specific instances and system implementations could be added to give more thorough possible upgrades. This change would need to be implemented into the GitHub and subsequently the vector stores that the workflow pulls from. These additions could include NIST control enhancements or SOX as examples, but they would need to be incorporated into the GitHub in new directories to allow the AI Agents to parse the supplemental information efficiently. This would also change the workflow slightly because new vector store tools would need to be added to the Recommendations AI Agent.
